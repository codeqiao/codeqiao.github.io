# 栖点网站维护

适用于仓库 https://github.com/codeqiao/codeqiao.github.io 。先确认当前工作区是该仓库，阅读仓库的 `AGENTS.md`、`README.md` 和相关实现，检查 Git 状态并保留用户已有的改动。以当前仓库规则为准；若已安装的本 Skill 与仓库 `skills/qidian-site/SKILL.md` 不一致，先阅读仓库版本并按其中规则操作。不要仅凭远程网站内容覆盖用户的其他本地文件。

## 内容流程

先检索现有栏目、文章和游戏，结合站主的目标及原内容的用途，自行判断新增还是修改：同一文章的补充、更正或同一游戏的功能、难度和体验迭代，通常修改原内容；独立主题、用途明显不同的新游戏或需独立访问的作品，通常新增。可在确有关系时补充引用。站主明确指定时按其要求处理，不机械套规则；无法判断且选择会改变原意或导致不可逆损失时先说明具体分歧并询问。交付时说明判断、改动和预览。

修改时先检查现有行为、文章含义及数据使用方式，保留相关功能、原有链接、点赞、存档和用户数据；确需不兼容调整时先规划迁移与验证，避免静默清除或覆盖。修正文章事实时保留上下文和出处，必要时注明更新时间；游戏修改验证原有玩法、新功能、触屏键盘及存档兼容性。

- 明确用户提供的内容、来源和目标栏目；不能凭空编造事实、个人经历或来源。涉及公开敏感内容或材料不足时，先处理不依赖这些材料的部分，并向站主询问必要信息。
- 博客和笔记放 `source/_posts/`，笔记使用合适分类。使用稳定且唯一的小写英文、数字和连字符 slug，填写标题、日期、描述及适当分类和标签；沿用已有格式。先检索相关文章，只在有实际知识关系时使用 `{% post_link slug %}` 或 `related` 引用，说明关联；构建会自动生成双向导航。不要为了凑链接建立无关引用。
- Skills、游戏和工具分别在 `source/skills/<slug>/index.md`、`source/games/<slug>/index.md`、`source/tools/<slug>/index.md` 新增或修改，front matter 必须含 `title`、`description` 和对应 `menu_id`，可选 `order`。列表在构建时自动生成，不手动修改栏目列表。游戏和工具应是可实际使用的静态前端，按需编写独立逻辑，适配触屏、键盘和小屏幕，避免不必要的重型依赖。
- 其他内容先查找仓库现有结构和约定；沿用合适的内容类型，确有需要才扩展结构。`listed: false` 只是隐藏列表，不会使页面私密。仓库和站点公开，不要提交凭据或未经授权公开的内容。
- 不随意变更已有文章 slug 或内容路径：知识链接、外部链接和点赞计数依赖它们。确需迁移时先规划映射及数据保留。只在本次工作相关且有证据时改进流程，并同步更新仓库文档和本 Skill 的源文件。

## 验证和交付

运行 `pnpm test`、`pnpm build`；检查新增内容的列表、详情及相关链接，涉及界面或交互时验证桌面与手机尺寸和主要操作。用本地服务提供可打开的预览；新增或修改栏目元信息后重启服务以刷新列表。若命令、环境或发布失败，准确报告，不声称成功。

仓库 `AGENTS.md` 的发布规则始终适用：先完成本地修改与预览，只有站主明确授权本次变更上线后，才能推送、合并或触发部署；旧授权不适用于后续变更。获授权后遵循仓库分支与检查要求，确认 GitHub Pages 部署和线上结果。
